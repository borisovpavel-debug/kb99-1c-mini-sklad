# kb99-1c-mini-sklad

Учебная конфигурация «Мини-Склад» на платформе **1С:Предприятие 8.3**: учёт товаров на складе по «Практическому пособию разработчика» Радченко и Хрусталёвой. Есть справочники, документы, регистры накопления с учётом партий по FIFO, отчёты на СКД, печатная форма, роли с ограничением доступа по складу и регламентное задание.

## Что внутри

| Объект | Тип | Назначение |
|---|---|---|
| Мини-Склад | Подсистема | Раздел интерфейса, в котором собраны все объекты |
| Товары | Справочник | Список товаров. Форма выбора показывает остаток каждого товара, товары без остатка выделены условным оформлением |
| Контрагенты | Справочник | Поставщики и покупатели: ИНН, КПП, контактная информация (телефон / почта) с проверкой при записи |
| Склады | Справочник | Склады, к которым привязаны документы и пользователи |
| Поступление | Документ | Приход товаров от контрагента на склад (табличная часть «Товары»: товар, количество, цена, сумма). Каждое поступление создаёт партию товара |
| Реализация | Документ | Расход товаров покупателю со склада, реквизит «Вид операции». Проводится по трём регистрам: остатки, партии, обороты. Партии списываются по FIFO, при нехватке товара документ не проводится. Кнопка «Подбор» добавляет товары из формы выбора, форма не закрывается после выбора |
| ВидыОпераций | Перечисление | Вид операции: поступление, реализация |
| ВидыКонтактнойИнформации | Перечисление | Телефон, почта |
| ОстаткиТоваров | Регистр накопления (остатки) | Количество товаров: приход при поступлении, расход при реализации |
| ПартииТоваров | Регистр накопления (остатки) | Партии по документам поступления: количество и стоимость. Реализация списывает партии от ранней к поздней |
| ОборотыТоваров | Регистр накопления (обороты) | Обороты по товарам, контрагентам и видам операций: количество, сумма, себестоимость продаж по FIFO |
| СкладыПользователей | Регистр сведений | Привязка пользователя к складу. На нём построены ограничения доступа (RLS) |
| СтатусыТоваров | Справочник (служебный) | Остаток и статус «В наличии / Нет в наличии» по каждому товару. Обновляется регламентным заданием |
| ИмяТекущегоПользователя | Параметр сеанса | Имя текущего пользователя, используется в условиях RLS |
| Администратор, Менеджер, Кладовщик, Гость | Роли | Права на объекты и ограничения доступа по складу |
| РаботаСТоварамиКлиент | Общий модуль (клиент) | Пересчёт суммы строки в формах Поступления и Реализации |
| РегламентныеПроцедуры | Общий модуль (сервер) | Процедура обновления справочника «Статусы товаров» |
| ОбновлениеСтатусовТоваров | Регламентное задание | Раз в минуту обновляет «Статусы товаров» |
| ОстаткиТоваровНаДату | Отчёт (СКД) | Остатки на выбранную дату: все товары справочника через левое соединение с остатками, количество и стоимость по партиям |
| ОборотыПоТоварам | Отчёт (СКД) | Приход и расход товаров за период |
| Печать накладной | Печатная форма | Печать документа «Реализация» |

Команды «Поступление: создать» и «Реализация: создать» выведены на панель действий подсистемы. Отчёты, печатная форма и списки регистров доступны в разделе «Мини-Склад». Обязательные реквизиты документов (склад, контрагент, табличная часть «Товары», товар, количество, цена) проверяются платформой при проведении.

## Структура репозитория

```
kb99-1c-mini-sklad/
```

Условное оформление списка товаров находится в `src/cf/Catalogs/Товары/Forms/ФормаВыбора/Ext/Form.xml` (подсветка строк с остатком 0 и меньше).

## Как открыть

1. Установите платформу **1С:Предприятие 8.3** (подойдёт и учебная версия).
2. Склонируйте репозиторий:
   ```bash
   git clone https://github.com/borisovpavel-debug/kb99-1c-mini-sklad.git
   ```
3. В окне запуска 1С нажмите **Добавить → Создание новой информационной базы → Создание информационной базы без конфигурации** и укажите любой пустой каталог.
4. Откройте базу в режиме **Конфигуратор**.
5. **Конфигурация → Открыть конфигурацию**, затем **Конфигурация → Загрузить конфигурацию из файлов…** Укажите каталог `src/cf` из репозитория.
6. Согласитесь на обновление конфигурации базы данных (**F7**).
7. Запустите **1С:Предприятие** (**F5**). Откроется раздел «Мини-Склад» со справочниками, документами и командами создания.

Пользователей и привязку к складам нужно создать самостоятельно (см. «Как проверить роли»).

## Как проверить FIFO

1. Создайте два поступления одного товара с разной ценой, например 10 шт по 100 и затем 20 шт по 95. Дата второго поступления не должна быть позже даты реализации.
2. Создайте реализацию этого товара на 15 шт.
3. Откройте список регистра «Партии товаров»: из первой партии списано 10 шт на 1000, из второй 5 шт на 475. В «Оборотах товаров» себестоимость продажи 1475.

## Как проверить подбор

1. Создайте реализацию и нажмите **Подбор**.
2. Откроется список товаров с колонкой «Остаток». Товары с остатком 0 и меньше выделены цветом (условное оформление в форме выбора справочника «Товары»).
3. Двойным щелчком выберите товар: в таблицу добавится строка с количеством 1. Если выбрать тот же товар ещё раз, количество в существующей строке увеличится, новая строка не создаётся. Форма выбора остаётся открытой.
4. Не заполняйте количество и цену и нажмите **Провести**: платформа покажет ошибки и не проведёт документ.

## Роли и права по складам

Склад хранится в реквизите «Склад» документов «Поступление» и «Реализация». Доступ к документам ограничен по складу (RLS): условие в ролях выбирает документы тех складов, которые записаны пользователю в регистре «Склады пользователей». Имя пользователя в условие попадает через параметр сеанса `ИмяТекущегоПользователя`, который заполняется в модуле сеанса.

| Роль | Поступление | Реализация |
|---|---|---|
| Администратор | полный доступ | полный доступ |
| Менеджер | просмотр документов своего склада | просмотр, ввод, изменение и проведение по своему складу |
| Кладовщик | просмотр, ввод, изменение и проведение по своему складу | просмотр документов своего склада |
| Гость | только просмотр документов своего склада | только просмотр документов своего склада |

Запись и изменение документа на чужой склад запрещены: платформа выдаёт «У пользователя недостаточно прав на исполнение операции над базой данных». Если у пользователя нет записи в регистре «Склады пользователей», он не видит ни одного документа.

Ограничение накладывается на документы. Регистры остатков и партий по складам не разделены.

### Как проверить роли

1. Запустите 1С:Предприятие под **Администратором** и создайте склады «Основной» и «Запасной».
2. В конфигураторе (**Администрирование → Пользователи**) создайте пользователей и назначьте роли: Администратор, Менеджер, Кладовщик (двух), Гость.
3. В 1С:Предприятие в регистре «Склады пользователей» укажите склад каждому пользователю. Имя в регистре должно совпадать с именем пользователя в базе.
4. Создайте по документу «Поступление» и «Реализация» на каждый склад.
5. Войдите под каждым пользователем: должны быть видны только документы своего склада. Кладовщик не может создать поступление на чужой склад, Гость не может создавать и изменять документы.

## Регламентное задание

Задание `ОбновлениеСтатусовТоваров` запускает процедуру `РегламентныеПроцедуры.ОбновитьСтатусыТоваров` раз в минуту. Процедура запросом получает остаток каждого товара из регистра «Остатки товаров» и записывает в справочник «Статусы товаров» остаток, статус и время обновления. Для каждого товара поддерживается одна запись: она обновляется, а не создаётся заново. В файловой базе задание выполняется, пока открыт хотя бы один клиент.

Проверка: откройте справочник «Статусы товаров», проведите документ, изменяющий остаток, подождите минуту и обновите список (**Еще → Обновить**): остаток, статус и время изменятся.

## Как сохранить изменения в репозиторий

1. Конфигуратор → **Конфигурация → Выгрузить конфигурацию в файлы…** → каталог `src/cf` (формат: иерархический).
2. Затем:
   ```bash
   git add .
   git commit -m "feat: <что сделано>"
   git push
   ```

Сообщения коммитов пишем по [Conventional Commits](https://www.conventionalcommits.org/ru/): `feat:`, `fix:`, `docs:`, `refactor:`.

## Чего нет в репозитории

Файлы базы (`*.1CD`), бинарные выгрузки (`*.cf`, `*.dt`) и журнал регистрации исключены через `.gitignore`. Хранится только исходный код конфигурации в XML.
